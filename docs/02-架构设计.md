## 1. 技术栈选型

| 层次 | 选型 | 说明 |
|---|---|---|
| 前端 | HTML5 SPA + 原生 JS + ECharts 5.5（本地 vendor） | 无 Node 构建依赖，后端静态托管；ECharts 已下载至 `web/vendor/echarts.min.js`（1.0MB），内网无外网依赖 |
| 后端 | Python 3.11+ / FastAPI + uvicorn | 自带 OpenAPI 文档（/docs）；单进程 + 写串行化即可支撑 50 并发 |
| 数据库 | SQLite 3，WAL 模式 + 外键约束 | 单文件 `data/jujie_energy.db`；自研轻量 DAO（参数化查询），不引 ORM |
| 会话 | itsdangerous 签名 Cookie（HttpOnly, SameSite=Lax, 8h 滑动续期） | 无服务端会话存储，强制下线靠 `session_revoked_at` 时间戳 |
| 认证 | 钉钉 OAuth2 扫码登录 + Mock 模式 + 管理员本地口令兜底 | 三层降级，见评审 R1 |
| Excel | openpyxl | 模板生成 / 解析校验 / 错误标注三合一 |
| PDF | reportlab + 内置 simhei.ttf | 纯 Python wheel，Windows/Linux 零系统依赖 |
| 测试 | pytest + httpx（ASGITransport 直连 FastAPI 应用） | 单元 / 集成 / 边界三轮 |

## 5. 核心业务流程

### 5.1 登录流
```
浏览器 → GET / → 未登录302登录页
登录页 → /api/auth/dingtalk/qr-url → 跳转钉钉扫码页(Mock时为/mock-scan页)
用户扫码确认 → 钉钉302回 /api/auth/dingtalk/callback?authCode
后端 authCode→unionId/昵称/手机号 → 匹配 sys_user:
  已绑定+active  → 签发Cookie→302工作台，写login_log
  已绑定+disabled→ 提示页"账号已停用"
  未绑定         → 按mobile匹配自动绑定；无匹配→创建pending用户→待开通页
```

### 5.1a 用户管理扫码绑定流（管理员主动为成员绑定）
```
管理员 → 用户管理「扫码绑定」→ POST /api/sys/users/{id}/ding-bind
       → 生成绑定态 state（auth_state.bind_user_id）+ 二维码/链接
成员用钉钉扫码 → callback 消费 state（含 bind_user_id）→ authCode 换 unionId
  unionId 已被他人占用 → /bind-result.html?err=冲突说明
  否则                 → UPDATE sys_user.ding_unionid → /bind-result.html?ok=1
  （绑定不签发会话；绑定后成员扫码登录直达工作台）
```

### 5.2 能耗台账审核状态机
```
draft ──submit──► submitted ──audit(approve)──► approved(锁定,编辑403)
  ▲                   │
  └──audit(reject+原因)┘  (rejected 可再次编辑→submit)
解锁：approved →(manager+ 手工 unlock, 写op_log)→ draft
```

### 5.3 年度碳盘查主流程
```
创建年度(自动) → 填报(manual/import/mapped 三来源,实时核算预览)
  → submit(盘查 submitted, 活动数据只读)
  → approve(审定: 封存 factor_snapshot+emission, inventory=approved)
  → 成为分析/分摊/导出的可用数据源
台账映射: 科目活动值 = Σ(该年 approved 台账 quantity × map_convert)   【评审M1】
绿电: 电力净量 = gross - lease - pv, 光伏减碳量 = Σpv × 电力因子       【评审M2】
```

### 5.4 Excel 导入五步流
```
下载模板(服务端按当前字典动态生成, Sheet2=字典说明)
 → 上传(≤10MB,.xlsx) → 解析+全量校验(表头/必填/类型/范围/字典/唯一)
 → 预览(新增N/覆盖M/错误K, 错误行可下载标注Excel)
 → 确认入库(策略: skip幂等 / overwrite覆盖) → import_task 留痕
```

## 6. 安全设计落地

- 全接口会话校验 + 逐接口角色装饰器 `require('admin','manager',...)`；填报员数据按 dept 过滤
- 参数化查询防注入；API 输出 JSON 无 HTML 注入面；前端渲染统一 `textContent`/转义
- 钉钉密钥 Fernet（AES）加密存储，密钥在 `data/secret.key`（0600 权限），接口不回显
- 操作日志覆盖：登录/台账提交审核/盘查提交审定/因子变更(前后值)/导入/导出/备份恢复/用户变更
- 密码 PBKDF2-HMAC-SHA256(10万轮) 哈希

## 7. 测试策略（三轮）

- 单元（test_calc.py）：核算公式、范围分组、因子年度取值与回退、快照封存、绿电净量、分摊/强度、map_convert 换算——以 §3.6 基准表为金标准，断言到 0.01
- 集成（test_api.py）：httpx 驱动真实 ASGI 全链路：登录→台账→审核→盘查→审定→分摊→模板→导入→导出→备份恢复
- 边界（test_edge.py）：401/403/409/400 全场景、非法值（负数/13月/字典外）、锁定后写、跳过策略幂等、超 100% 分摊 warning
